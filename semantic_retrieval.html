Creative Semantic Retrieval: The Midnight Museum¶

Part A: Mini Project, Question 1 (Creative Semantic Retrieval) Student: <name / ID>

A visitor describes a feeling, such as "the loneliness of an empty train station at 3 AM", and the system returns the 5 most similar works from a museum of 125 poems, paintings, photographs, sound clips, sculptures and film scenes (each described in text).

How it works:

  1. Embed: turn every item and the query into a vector (a list of numbers) with a pretrained model.
  2. Compare: measure how close the query vector is to each item vector with cosine similarity.
  3. Rank: sort the items from most to least similar.
  4. Return the top 5.

What we test: four ways of making vectors (TF-IDF, BERT, MiniLM and GTE-large) on 14 queries. Each query targets a different challenge: literal, abstract, metaphor, negation, opposite mood on the same topic, paraphrase, a "sound clip only" request, one ambiguous word, and a query in Arabic. Some items are deliberate decoys: they share words with a query but not its meaning. This lets us check whether the system finds meaning or just matching words.

Key findings:

  • The best model, GTE-large, reaches nDCG@5 = 0.74 and P@5 = 0.69. For comparison: MiniLM 0.48 / 0.45, TF-IDF 0.18 / 0.17, random 0.06 / 0.08.
  • Embeddings work very well when the feeling is stated through things the items describe. Awe, anger at injustice and nostalgia are all perfect (1.00), with no shared keywords.
  • They fail when the meaning must be inferred: metaphor (0.48), humour (0.52), and a query in Arabic (0.00).
  • "not" and opposites barely register: "a night that is lonely" and "a night that is not lonely" get a similarity of 0.95–0.97.
  • The models group the works by form more than feeling: an item's closest neighbour is the same kind of work (poem, sound clip, …) 92% of the time, but has the same emotion only 17% of the time.

3. Step 1: Turn text into vectors (embeddings)¶

We compare four ways of turning text into vectors:

Name How it works
TF-IDF One number per vocabulary word, based on how often the word appears. Two texts only look similar if they share the exact same words.
BERT A general language model. It reads words in context but was never trained to make similar sentences get similar vectors.
MiniLM, GTE-large Models trained on millions of sentence pairs so that texts with similar meaning get similar vectors, even when they use different words.

For the three transformer models, model.encode(texts) does the following: split the text into tokens → run the transformer → get one vector per token → average the token vectors into one vector for the whole text (mean pooling). BERT has no ready-made sentence version, so sentence-transformers adds the same averaging step for it.

    "MiniLM": SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2"),   # small sentence-embedding model

}
for model in transformer_models.values():
    model.float()   # use full 32-bit precision, so the results are the same on every computer

# Keyword baseline: TF-IDF, learned from the words in our collection
tfidf = TfidfVectorizer(stop_words="english", sublinear_tf=True).fit(items["text"])


def embed(texts, model_name):
    """Turn a list of texts into a matrix of vectors (one row per text)."""
    if model_name == "TF-IDF":
        return tfidf.transform(texts).toarray()
    return transformer_models[model_name].encode(texts)


MODELS = ["TF-IDF", "BERT", "MiniLM", "GTE-large"]
FINAL_MODEL = "GTE-large"

4. Step 2: Cosine similarity¶

Cosine similarity measures the angle between two vectors: 1 means they point the same way (very similar), 0 means unrelated.

$$\cos(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a}\cdot\mathbf{b}}{\lVert\mathbf{a}\rVert\,\lVert\mathbf{b}\rVert}$$

If every vector is first scaled to length 1, the cosine is just the dot product. That lets us compare many vectors at once with a single matrix multiplication.

In [6]:
def normalize(vectors):
    """Scale every row to length 1."""
    lengths = np.linalg.norm(vectors, axis=1, keepdims=True)
    return vectors / np.maximum(lengths, 1e-10)    # the max(...) avoids dividing by zero


def cosine_similarity(a, b):
    """Cosine similarity between every row of a and every row of b."""
    return normalize(a) @ normalize(b).T


# Quick check against the formula written out by hand
a, b = np.array([[1.0, 2.0, 3.0]]), np.array([[2.0, 0.0, 1.0]])
by_hand = (a @ b.T) / (np.linalg.norm(a) * np.linalg.norm(b))
print("our function:", cosine_similarity(a, b)[0, 0].round(4), "| formula:", by_hand[0, 0].round(4))

5. Steps 3 and 4: Rank the items and return the top 5¶

In [7]:
def rank_items(query_text, model_name):
    """All item ids sorted from most to least similar to the query, with their scores."""
    query_vector = embed([query_text], model_name)
    scores = cosine_similarity(query_vector, item_vectors[model_name])[0]
    order = np.argsort(-scores, kind="stable")    # highest score first (ties keep dataset order)
    return items.index[order], scores[order]


def search(query_text, model_name=FINAL_MODEL, k=5):
    """The top-k items for a query, as a small table."""
    ids, scores = rank_items(query_text, model_name)
    top = items.loc[ids[:k], ["type", "title"]]
    top["score"] = scores[:k].round(3)
    return top

def judge(query, item_id):
    """Manual relevance mark for one retrieved item, from the labels in queries.json."""
    if not query["relevant"]:
        return ""                                  # Q11 has no labels
    grade = query["relevant"].get(str(item_id), 0)
    if grade == 2:
        return "✓"
    if grade == 1:
        return "~"
    if item_id in query["decoys"]:
        return "✗ DECOY"
    return "✗"


def show_results(query, models=("GTE-large", "MiniLM", "TF-IDF")):
    print(f"\n{query['qid']} ({query['category']}):  \"{query['query']}\"")
    print(f"Intended meaning: {query['intent']}")
    table = {}
    for name in models:
        ids, scores = rank_items(query["query"], name)
        table[name] = [f"{judge(query, i)}  {items.loc[i, 'title']} ({items.loc[i, 'type']}, {s:.2f})"
                       for i, s in zip(ids[:5], scores[:5])]
    display(pd.DataFrame(table, index=[1, 2, 3, 4, 5]))

7. Evaluation¶

We score each ranking with three simple measures:

  • P@5 (precision at 5): how many of the top 5 are relevant (✓ or ~), from 0 to 1.
  • nDCG@5: like P@5, but ✓ counts more than ~ and higher positions count more; 1.0 is the perfect top 5.
  • Decoys@5: how many decoys made it into the top 5. This measures "related to the topic but not the intended meaning".

A random ranking (average of 200 shuffles) shows the chance level.

In [9]:
def evaluate(query, ranked_ids):
    """P@5, nDCG@5 and Decoys@5 for one ranked list of item ids."""
    top5 = list(ranked_ids[:5])
    grades = [query["relevant"].get(str(i), 0) for i in top5]

    # nDCG: each result earns (2^grade - 1), discounted by its position; divide by the best possible score
    dcg = sum((2 ** g - 1) / np.log2(position + 2) for position, g in enumerate(grades))
    best_grades = sorted(query["relevant"].values(), reverse=True)[:5]
    best_dcg = sum((2 ** g - 1) / np.log2(position + 2) for position, g in enumerate(best_grades))

    return {
        "P@5": sum(g > 0 for g in grades) / 5,
        "nDCG@5": dcg / best_dcg,
        "Decoys@5": sum(i in query["decoys"] for i in top5),
    }

8.1 Does the model group the works by feeling, or by form?¶

For every item we find its closest neighbour (highest cosine similarity) and check whether the two have the same hidden emotional theme and whether they are the same type of work (poem, photograph, …). We repeat this using the description alone, without the "Poem: Title." prefix, to see how much of the grouping comes from that prefix.

def closest_neighbour_check(vectors):
    similarity = cosine_similarity(vectors, vectors)
    np.fill_diagonal(similarity, -np.inf)          # an item cannot be its own neighbour
    closest = similarity.argmax(axis=1)
    return {"same theme": (themes[closest] == themes).mean(), "same type": (types[closest] == types).mean()}


def chance(labels):
    """Probability that two different, randomly picked items share a label."""
    counts = pd.Series(labels).value_counts()
    return (counts * (counts - 1)).sum() / (len(labels) * (len(labels) - 1))

9.2 What types of queries produced good or poor results?¶

Good (GTE-large nDCG@5 ≥ 0.83): awe (Q3), anger at injustice (Q4), English nostalgia (Q13), grief sound clip (Q6), the literal nature query (Q5), joyful rain (Q9) and homecoming (Q10). In all of these, the feeling is stated using ideas that the item descriptions actually show, even if in different words: universe ↔ galaxies, injustice ↔ eviction, belong ↔ his mother recognises his walk. TF-IDF cannot make these links, because it needs the same words, so it scores between 0.00 and 0.21 on most of these queries. (Q7 also scores 0.91, but for the wrong reason; see 9.4.)

Middling (0.65–0.68): queries that combine a feeling with a concrete place or thing (Q1 lonely + train station, Q2 bittersweet + childhood summer). The concrete words are strong signals, so items with the right setting but the wrong mood compete with the right ones.

Poor: queries where the meaning has to be worked out rather than read from the words:

  • the metaphor (Q8, 0.48): TF-IDF, MiniLM and GTE-large all found only the one item that shares the words "house" and "lights";
  • humour (Q12, 0.52): the joke is in the situation (a sock with lawyers), and no description says "funny";
  • Arabic (Q14, 0.00);
  • the single word "blue" (Q11), where the model quietly picks one meaning.

Bigger models help most on harder queries. MiniLM and GTE-large are similar on easy, keyword-rich queries (Q9: 0.86 vs 0.85). The gap is large on paraphrases and setting-heavy queries (Q10: 0.37 vs 0.83; Q1: 0.19 vs 0.65; Q5: 0.36 vs 0.86), where the small model leans more on matching words ("morning" → Morning After, "train" → Rush Hour).

9.3 Did the system retrieve items related to the topic but not the intended meaning?¶

Yes, and the decoy count measures exactly this. Over the 13 scored queries, decoys took 7 top-5 places for GTE-large, 9 for MiniLM and 10 for TF-IDF, against about 1.4 by pure chance. The decoys follow a clear pattern: they share an obvious word or setting with the query but carry a different or even opposite feeling:

  • train / station → a packed rush-hour train, a friendly sleeper compartment, a family reunion on a platform (Q1)
  • house + lights → a joyful power-cut party, a lamp left on for a traveller (Q8)
  • rain → calm rain on a roof, rain at a funeral (Q9)
  • laughing → a driver laughing in panic, a man who laughs and then cries at an old cartoon (Q12)
  • home → MiniLM finds Departure, a woman leaving her hometown (Q10), the exact opposite

BERT has the fewest decoys (4), but not because it understands the query. Its results are poor overall (P@5 = 0.32), so it rarely finds any item on the right topic, decoy or not.

The Arabic query is a special case. The model cannot read it: the tokenizer breaks it into 20 single letters (Section 8.5). Yet the results are not random. All three transformer models rank Caravan at Night in their top 5, MiniLM and GTE-large both put Desert Dawn first, and GTE-large also returns Mother Tongue and The Eid Express. The models link Arabic writing with desert and Middle-Eastern scenes, so they retrieve by a cultural association instead of by meaning. This is a small, real example of bias in embeddings.

9.4 Which semantic relationships were captured well, and which poorly?¶

Captured well

  • Same idea, different words: vastness of the universe ↔ thousands of galaxies; grief ↔ a saved voicemail from a father who has died. TF-IDF completely misses these.
  • Paraphrase: "coming back to the place where you belong" vs "returning home after years away" scores 0.875 with GTE-large, well above its score for an unrelated pair (0.709). TF-IDF scores the same pair 0.
  • Related feelings: in Section 8.1, the closest theme to grief is loneliness at night, nostalgia and time/decay are each other's closest theme, and fear and urban anxiety are closest to loneliness at night. The model has a rough sense of a "melancholy" family of feelings.
  • Explicit type words: "sound clip" reliably brings back sound clips (5/5 for GTE-large, MiniLM and TF-IDF), because the type is written in each item's text.

Captured poorly

  • Negation: "a night that is lonely" vs "a night that is not lonely" scores 0.95–0.97 for every transformer model, higher than the real paraphrase pair. Searching with and without "not" gives almost the same top 5 (3 of 5 shared for GTE-large, 4 of 5 for MiniLM).
  • Opposites: lights on vs lights off scores 0.98 and coming home vs leaving home scores 0.90 (GTE-large). Opposites share a topic, so they end up close together.
  • Word order / who does what: "the child comforts the old man" vs "the old man comforts the child" scores 0.97–0.98. Averaging the token vectors loses most of the word order.
  • Metaphor, humour and hidden meaning: the depression painting is missed for the metaphor query, and a soldier's homecoming told only through actions is missed for Q10. These need reasoning, not just matching ideas.
  • Balancing two conditions: in Q6, "sound clip" outweighs "grief". A joyful wedding recording (MiniLM) and a nostalgic ice-cream van (GTE-large) beat grief items of other types; the best of those is at rank 7 for GTE-large and 27 for MiniLM.
  • Form over feeling: the model groups the works by what they are and how they are written, not by how they feel. An item's closest neighbour is the same type of work 92% of the time with GTE-large (chance: 17%), but has the same emotion only 17% of the time (chance: 6%). Even with the "Poem:" prefix removed, 50% of neighbours are still the same type: poems are grouped by their line-break style, and sound clips by words like "recording". The t-SNE maps show this: tight clusters by type, scattered points by theme. Themes about a shared subject (night scenes, nature, space) stick together; themes about a tone (humour, fear, anger) barely do. Funny items are even slightly less similar to each other than two random items.

9.5 Limitations and failure cases¶

  1. Similar is not the same as relevant. Cosine similarity measures shared topic. It is blind to "not", to opposites and to who does what, which is often exactly what an emotional query depends on.
  2. Metaphor, irony and humour are out of reach, because they need reasoning about what a text implies.
  3. Obvious words and writing style dominate: train, night, morning, burning, rain, laughing. A bigger model reduces this but does not remove it.
  4. Scores have no fixed meaning. GTE-large gives almost every pair between 0.70 and 0.91: an unrelated pair scores 0.709, and the unreadable Arabic query's top result scores 0.79, almost as high as the best correct English match (0.81). BERT gives everything a similar score (0.30–0.78), with a gap of only 0.017 between relevant and non-relevant items. So there is no threshold for "no good match": the system always returns five items, even when it understood nothing.
  5. English only. The Arabic query scores 0.00 for every model, and the failure is silent: the results look normal but are driven by bias.
  6. Descriptions stand in for the real works. The system searches descriptions of paintings and sounds, so the results depend on how well they are written. A real museum would need image and audio models such as CLIP or CLAP.
  7. Evaluation limits. The collection (125 items) and the query set (13 scored queries) are small. One person wrote the items, the queries and the labels, and emotional relevance is subjective. Decoys were added on purpose, so the scores are probably lower than on a normal collection. The comparisons between models and query types are the reliable findings.
  8. Speed. GTE-large is 15× bigger than MiniLM and much slower on a CPU. That is fine for 125 items, but a large catalogue would need a GPU and a fast vector index.

9.6 What would help, based on the experiments¶

  • Rewrite the query in plain words before searching (for example, with an LLM). Stating the metaphor's meaning raised Q8 from 0.48 to 0.80 and removed all decoys. Translating the Arabic query raised it from 0.00 to 1.00.
  • Apply hard conditions like "sound clip" as a filter, then rank only the matching items by similarity.
  • Re-rank the top ~20 with a cross-encoder, a model that reads the query and the item together and can therefore notice "not" and word order.
  • Use multilingual models for non-English visitors, and image/audio models to search the works themselves.

9.7 Conclusion¶

Embeddings turn "find something that feels like this" into a nearest-neighbour search, and it works well when the feeling is expressed through ideas the items describe. GTE-large reaches nDCG@5 = 0.74, compared with 0.18 for keyword matching and 0.06 for random, and it is perfect on awe, injustice and nostalgia without any shared keywords. But embeddings capture what a text is about much more than what it says about it: negation, opposites, word order, metaphor and humour barely change the vectors. They also group works by form more than by feeling, and they cannot tell when they have not understood a query. They are a strong first step for creative search, but they need help (query rewriting, filters and re-ranking) to reliably find the intended meaning.
